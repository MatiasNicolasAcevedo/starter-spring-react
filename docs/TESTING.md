## Elegir pruebas para una tarea pequeña

Frontera indica en cada tarea la capa, el riesgo que demuestra y comandos exactos; Junie los ejecuta sin decidir otra estrategia. Elegir la menor capa que observe el comportamiento, reutilizando fixtures y regresiones existentes:

| Cambio/riesgo | Prueba nueva pertinente | Iteración desde la raíz (Git Bash) |
|---|---|---|
| Regla o transformación sin infraestructura | Unitaria con caso útil y borde/error | `cd server && ./mvnw -Dtest=NombreTest test` o `npm --prefix client test -- --run src/ruta.test.ts` (sustituir ruta/nombre en la tarea) |
| Interacción/estados de pantalla | Componente con providers reales, Testing Library y MSW | `npm --prefix client test -- --run src/ruta.test.tsx` y `npm --prefix client run typecheck` |
| Persistencia, contrato HTTP, permisos o CSRF | IT PostgreSQL/HTTP real y negativo de actor/regla | `cd server && ./mvnw -Dit.test=NombreIT verify` con Docker, después gate backend de cierre |
| Recorrido principal o riesgo entre capas | Playwright con API/DB/OIDC propios reales | La tarea fija la receta aislada; `bash scripts/verify.sh --e2e` conserva el conjunto y cleanup |

Los ejemplos con nombres son patrones para planner, no comandos pendientes de interpretar por Junie. JDK21 y dependencias host para Maven; `npm ci --prefix client` antes de Vitest host. Alternativa containerizada y trampas: SETUP. No exigir E2E nueva por cada cambio, duplicar un mismo caso en todas las capas ni crear tests triviales que reflejen la implementación. Conservar las regresiones existentes de seguridad/persistencia y todos sus umbrales. Una prueba dirigida verde solo acredita ese alcance.

La revisión de carga local del 2026-10-19 conserva un FULL de cierre técnico: el inicializador y scripts operativos afectan ambas capas y aislamiento. El costo histórico C35m38s/D40m58s puede variar; no prometer reducción sin medir. Se elimina la repetición por rutina y la actualización de cuatro documentos por cambio pequeño. No se introduce otro dispatcher ni un gate parcial equivalente a FULL. E y la adopción T-000 mantienen aceptación FULL propia.

## Validación local y CI liviana · decisión del dueño 2026-10-18
La validación pesada se hace en local. El dueño pidió optimizar para MVP pequeños, reducir esperas y ejecuciones de Actions. Esta decisión sustituye la repetición obligatoria de FULL en CI/implementer/reviewer; conserva la aceptación funcional, las suites, negativos, assertions, cobertura y revisión independiente. No modifica el ruleset ni sus permisos.

| Momento | Verificación exigida |
|---|---|
| Iterar o diagnosticar | Tests directamente relacionados; ejecutar solo la capa afectada. Un fallo se investiga antes de repetir, sin lanzar FULL para buscar un verde |
| Cerrar cambios técnicos de una tarea | Un FULL local sin opciones con todas las suites verdes, logs saneados, base/HEAD y huella técnica antes/después. Si falla, el gate se detiene y las suites siguientes quedan NO EJECUTADAS |
| Editar solo documentación después de ese FULL | docs-check y checks afectados; conservar evidencia y comprobar que las fuentes técnicas y base siguen idénticas. No repetir FULL por el nuevo SHA documental |
| Revisión independiente | Revisar código publicado y evidencia local, ejecutar pruebas dirigidas a riesgos/bordes y negativos. Repetir FULL solo ante cambio técnico/base, evidencia insuficiente o un riesgo concreto documentado |
| Publicar el PR | CI automática liviana `verify-required` verde sobre HEAD/base exactos; evidencia local FULL en tarea/PR y veredicto independiente antes del merge |
| Confirmación remota extraordinaria | FULL remoto manual, solo por decisión explícita; no requisito ordinario de cada tarea |

El FULL local sigue siendo `bash scripts/verify.sh`: docs, backend `clean verify` (incluidas IT PostgreSQL y JaCoCo), client typecheck/lint/formato/tests/cobertura/build e integración local/Playwright. `--fast` y suites sueltas no equivalen a FULL. Una corrección técnica después del FULL invalida su cierre; una transición solo documental conserva la evidencia si la base y huella técnica coinciden. Al cambiar base, revalidar la combinación; no reutilizar evidencia de otra base sin comprobar lo afectado.

**CI automática:** [ci.yml](../.github/workflows/ci.yml) solo se dispara por PR a main. Un único job `verify-required`, sin instalar dependencias de la aplicación ni levantar Docker: matrices Node de herramientas/contrato, docs-check y clasificación del diff. Usa checkout del HEAD real, acciones fijadas, concurrencia con cancelación y timeout 5 minutos. No vuelve a ejecutar FULL por push de rama o merge a main. Un PR draft puede tener esta CI verde: GitHub impide mergear drafts y ese verde acredita únicamente CI liviana.

**Límite del check:** `verify-required` no verifica por sí solo que se ejecutó FULL local. La evidencia local y su comprobación por el revisor son una condición adicional de merge en [AUTONOMY](AUTONOMY.md). Se acepta explícitamente esta dependencia del proceso local para el proyecto personal; no añadir un sistema de atestaciones, runners permanentes ni permisos nuevos. Un check liviano verde nunca se anuncia como seis suites de producto verdes.

**FULL remoto opcional:** [full.yml](../.github/workflows/full.yml), exclusivamente `workflow_dispatch`, conserva backend/client/E2E y el agregado estricto `full-result`; no corre en push, PR ni calendario. `scripts/ci/verify-required.mjs` y sus negativos se conservan para ese agregado: FULL exige todos sus jobs success y DOCS_ONLY exige suites técnicas skipped. Una omisión/fallo/cancelación exigida nunca cuenta como verde. El workflow manual se podrá despachar desde GitHub cuando exista en main; no se lanza para probar este cambio.

El clasificador `scripts/ci/classify-diff.mjs` distingue FULL/DOCS_ONLY sobre `base...head`. DOCS_ONLY acepta solo archivos regulares A/M de Markdown raíz/docs, AGENTS/CLAUDE conocidos y LICENSE. Código, workflows, scripts, Markdown técnico, lockfiles, renombres/borrados, modos especiales, diff vacío o errores exigen FULL local. La clasificación publicada no incorpora cambios locales sin commit: antes de cerrar una entrega incluir todo el árbol técnico que se publicará.

**Tiempo y costo:** GitHub documenta que los runners estándar de repositorios públicos son gratuitos: [facturación](https://docs.github.com/en/billing/concepts/product-billing/github-actions). Este repo se comprobó PUBLIC y usa ubuntu-24.04; no consume la bolsa de 2.000 minutos de repositorios privados por ese cómputo. Futuros MVP privados sí deben verificar su plan. No confundir esta regla con almacenamiento/artefactos u otros servicios. El beneficio principal aquí es evitar esperas y repetición; ahorro de duración pendiente de medir, sin porcentaje prometido.

## Reglas y negativos
Bugfix primero rojo pertinente, luego arreglo mínimo. Datos ficticios propios, Clock inyectado, sin orden/red externa/retries arbitrarios. Capturar exit real del proceso, no de una tubería.
Clasificador/agregado: node --test scripts/ci/*.test.mjs, matrices y mutantes heredados conservados. Saneador: canarios Python en la imagen E2E; export solo por allowlist/auditoría, sin tokens/cookies/claims. Lifecycle: scripts/test-e2e-lifecycle.sh cubre startup/readiness/runner/TERM/cleanup/segunda ejecución y rechazo de recursos existentes. Dev: test-dev-auth nginx/vite prueba login/recarga/restart/rebuild/retoma y HMR con restauración.
docs-check propio valida 22 criterios heredado/pendiente/verificado/bloqueado, evidencia propia para verificado, NO_LISTO mientras falte uno, tarea/tablero/STATUS/CI coherentes. Pruebas dirigidas alteran copia temporal sin kit/Git/artefactos y exigen rechazo de criterio ausente, herencia falsa y conteo incorrecto.
Proxy outage solo stack de ensayo propio: IP cacheada y DNS frío devuelven 502/504 dentro de 3s; restaurar y exigir 200. No acredita lectura upstream ni Google real.
Trampas y cleanup: [SETUP](SETUP.md#trampas-conocidas). Cambios en condición de HANDOFF revalidan o acotan ese criterio en el mismo PR. Revisión de sesión distinta sobre SHA/base comprobados; beta en D y adopción en E requieren FULL local y CI liviana según esta política, sin excepciones por etiqueta.
